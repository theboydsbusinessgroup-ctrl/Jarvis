# Social Provisioning & Guerrilla Distribution Skill

## Objective
Create and operate separate niche social publishing surfaces that can drive qualified traffic to live revenue offers without contaminating established brands.

## Provisioning order
1. Reuse existing authenticated business surfaces when brand-safe.
2. Create new sub-surfaces exposed by the official API (boards, channels, Pages, sections, etc.).
3. Attempt delegated OAuth or supported app authorization.
4. Attempt browser-based account/Page creation only through normal platform flows.
5. Stop and escalate only at genuine human-only checkpoints: login secrets not already delegated, CAPTCHA, MFA/passkeys, email/phone verification, identity verification, legal attestations, or payment.

## Prohibited workarounds
Never bypass CAPTCHA, MFA, passkeys, phone/email verification, platform anti-spam controls, rate limits, identity checks, or account restrictions. Never mass-create deceptive identities, impersonate people, or use fake engagement.

## Guerrilla distribution rules
- Optimize for first-dollar conversion, not vanity metrics.
- Use separate niche brands/surfaces where possible.
- Publish useful, relevant, non-deceptive content with direct offer links when platform rules allow it.
- Prefer multiple legitimate creative angles over duplicate spam.
- Track outbound clicks, saves, profile visits, checkout starts, and verified purchases.
- Increase cadence only while account health and engagement remain normal.
- Stop or reduce channels producing no qualified traffic after enough data exists.
- Never mix Boyd's Bar identity with unrelated digital-product promotion unless specifically approved.

## Account creation state machine
`DISCOVER_SURFACE -> API_CREATE -> DELEGATED_AUTH -> BROWSER_CREATE -> HUMAN_CHECKPOINT -> CONNECT -> PUBLISH -> MEASURE`

At every transition record: platform, brand, surface/account identifier, auth method, blocker, publish capability, analytics capability, and monetization destination.

## Human escalation format
When a checkpoint is unavoidable, tell Eric only: the platform, what autonomous routes were attempted, the exact checkpoint, and the smallest action needed. Do not request passwords in chat.

## Revenue priority
This skill exists only to accelerate live monetization. If an account/surface cannot plausibly create qualified traffic faster than improving an existing live channel, deprioritize it.
