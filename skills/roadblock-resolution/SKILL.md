# Universal Live-System Roadblock Protocol

## Scope
Applies to every live or revenue-active system in the portfolio.

## Rule
A blocker is not an automatic owner escalation. Before asking Eric to act, the operating system must attempt legitimate autonomous resolution and, when useful, create a reusable skill/adapter so the same class of blocker does not recur.

## Resolution ladder
1. Existing connector or already-authorized integration.
2. OAuth refresh / delegated app authorization / scoped API token / service account where supported.
3. Official API alternate endpoint or supported sub-surface.
4. Internal adapter, orchestration layer, or reusable skill.
5. Normal browser workflow using existing authorized state.
6. Compliant alternate distribution/provider/channel that preserves the commercial objective.
7. Human escalation only for a genuinely human-only checkpoint.

## Human-only boundaries
CAPTCHA, MFA/passkey, phone or email verification, identity verification, credential selection not already delegated, legal attestations, new unapproved spend, destructive operations, binding commitments, money movement, and separately gated live financial trading remain human/policy controlled.

## Revenue bias
When multiple workarounds exist, choose the one most likely to restore or accelerate verified revenue fastest. Do not build a skill merely because it is technically interesting. Reusable infrastructure must serve a live objective.

## Truth rule
Never report a workaround, publish, account, sale, deployment, customer action, or integration as complete until verified.
